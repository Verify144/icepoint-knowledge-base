internal/builder/builder.go (9240 bytes):
- Engine: runs building process with bot (icepointg79 bot), building data, config
- Run(ctx): Main execution loop
  1. Wait for OP (execute run list detection)
  2. Set gamemode 1 (creative mode)
  3. TP to drop position (execute in overworld run tp)
  4. Optional pre-clear (fill ... air for bounding box)
  5. Build chunks in snake (boustrophedon) order
  6. Build by chunk: setblock commands for normal blocks
  7. Complex NBT blocks: structure save/load transport
  8. Command blocks: CommandBlockUpdate writing
  9. SubChunkRequest comparison every N chunks
  10. Auto-reconnect (max 8) with breakpoint resume
- Statistics tracked: placedBlocks, skipped (unmapped), autoFixed (similar), fixed (inconsistent), nbtMissing
- Progress reporting: every 5% bucket

=== RELATION TO ICEPOINT ECOSYSTEM ===
This is the top-level application that uses:
- glacier (command engine) for sending commands
- icepointg79 (client) for connecting to rental servers
- IceStructure (parser) for reading building files
- glacier-winter (NBT) for block state encoding
- BlockMap (mapping) for Java <-> Bedrock state IDs
- icepoint-minecraft-kernel (auto-update) for client updates

=== KEY ARCHITECTURE NOTES ===
- Uses SnakeChunkOrder for efficient chunk building
- Uses SubChunkRequest for verification and rebuild
- Uses structure save/load for complex NBT blocks
- Uses setblock command stream for normal blocks
- Uses CommandBlockUpdate for command block text
- Supports auto-reconnect (8 times max) with breakpoint resume
- Tracks statistics: placed, skipped, fixed, autoFixed, nbtMissing
